# Contents

A complete inventory of the bootcamp. For *how to run* it see [README.md](README.md);
for the day-by-day teaching order see [CURRICULUM.md](CURRICULUM.md) and
[ADAM_CURRICULUM.md](ADAM_CURRICULUM.md).

The course covers **two standards** — SDTM (tabulation) then ADaM (analysis) — across
**two synthetic studies**: ABC-01 for teaching, DEF-01 for the independent capstone.

| | |
|---|---|
| Presentations | **18 decks** |
| SAS programs | **23** (+19 markdown walkthroughs, +19 answer keys) |
| Datasets | 7 raw → **8 SDTM** → **5 ADaM** (ABC-01) · 5 raw → **6 SDTM** (DEF-01) |
| Submission artifacts | define.xml ×2, aCRF + blank CRF, cSDRG |
| Quality harnesses | **5** automated checkers |
| Interactive tools | **3** browser artifacts |

## 4. Capstone — `capstone/`

**Study DEF-01** — Type 2 diabetes, larger, built independently with no walkthrough.
5 raw files → 6 SDTM domains (DM 6 · EX 7 · AE 7 · SUPPAE 7 · VS 96 · LB 32 rows).

| File | Purpose |
|---|---|
| `README_capstone.md` | the student brief: what to build, how to check |
| `data/def01_data_dictionary.md` | the raw data documentation |
| `notebooks/00_setup_capstone.sas` | paths and checks |
| `notebooks/13_capstone_DEF01_SKELETON.sas` | the starting point |
| `notebooks/verify_capstone.sas` | self-check against the reference |
| `oda_upload/sdtm_capstone_INSTRUCTOR_oda.zip` | ⛔ **instructor only** — contains the solution, so the capstone can be re-validated on ODA. Never hand this to a trainee. |

The raw data contains **four deliberate traps**, each one something ABC-01 never had, so a
trainee who copies their ABC-01 programs unchanged fails at all four:

| | Trap | What it tests |
|---|---|---|
| 1 | Units collected per site — site 02 uses lb / °F | `--ORRES` keeps the collected value, `--STRESN` standardises |
| 2 | One subject dosed twice, with an interruption | structure carries the meaning, not a flag |
| 3 | An adverse event dated only to a month | keep the partial date, derive nothing you cannot know |
| 4 | Abnormal labs that are not adverse events | the boundary between a finding and an event |

**These are told to the trainee**, in `def01_data_dictionary.md` and again in
`README_capstone.md` — as a real study spec would. The exercise is not to guess them but to
implement them correctly; `verify_capstone.sas` fails if any is handled wrong.

> The solution program and answer key are **excluded** from the shared copies.

## 6. Interactive tools — `interactive/`

Self-contained HTML — no server, no dependencies, generated from the real study data.

| Tool | What it does |
|---|---|
| **`subject_journey_dashboard.html`** | **Patient profile.** Pick a subject: their whole trial on one timeline — dosing, adverse events (severity-coloured, serious and treatment-emergent marked), con meds, visits — plus vitals and labs as trend charts with reference bands. Toggle tracks, filter to serious/treatment-emergent/abnormal, switch study-day ↔ calendar, zoom and pan. A **cohort view** stacks all 8 subjects for triage; click any row to open that subject. |
| `sdtm_lineage_explorer.html` | Pick any of 125 variables and trace its lineage: source CRF field → mapping rule → SDTM value, shown against a real record. |
| `ae_mapper.html` | An AE mapping exercise. Superseded by the dashboard; kept for reference. |

## 8. Quality harnesses

Nothing in this course is hand-maintained where it can be generated and checked.

| Script | Checks |
|---|---|

| `notebooks/sas/check_sas_static.py` | **191** static checks over the SAS programs |
| `data/audit_adam.py` | **91** — the ADaM equivalent |

## Validation status

The entire course has been **executed on SAS OnDemand for Academics**
(SAS 9.04.01M8P022223, Linux x64) — all SDTM domains and all ADaM datasets reproduce
their reference data exactly, with zero errors and zero warnings.

That run mattered: it found **11 defects that static analysis could not see**, because
they were SAS *execution* semantics rather than logic — a `RENAME` collision that SAS
only warns about, a `LENGTH` after `MERGE`, a numeric read that silently dropped a
significant figure. Three of the four SDTM defects announced themselves as WARNINGs
while the run reported success.

**A clean-looking run is not a correct run.** That lesson is the reason the harnesses
above exist, and it is taught explicitly in the QC notebook.

## A note on the data

Every dataset here is **synthetic**, generated for teaching. There is no real patient
data anywhere in this repository. Dictionary-coded values (`AEDECOD`, `CMDECOD`)
resemble MedDRA and WHODrug terms but were assigned for illustration — real coding
requires licensed dictionary versions and trained coders.
