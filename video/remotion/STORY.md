# Clinical Statistical Programming — story animation

An animated explainer that introduces clinical statistical programming by following
**one blood-pressure reading** (Subject ABC-01-001) from a patient's bedside to FDA
approval. Composition id: **`ClinStatStory`**.

## Output
- `out/clinical_stat_programming.mp4` — 1920×1080, 30 fps, **~154 s with ElevenLabs voiceover** (H.264 + AAC stereo, ~15 MB). Scene lengths are driven by the narration (see below).

## Scene order (edit pacing in `src/Story.jsx` → `SCENES`)
| # | File | Beat |
|---|---|---|
| 1 | `S01_Hook` | "How a single number helps approve a medicine" |
| 2 | `S02_Role` | The programmer = the bridge between medicine and evidence |
| 3 | `S03_Phases` | Clinical trial phases 1–4 (growing cohorts) |
| 4 | `S04_Born` | Collection: patient → EDC → raw data |
| 5 | `S05_Messy` | Raw data is messy (mixed dates, codes, free text) |
| 6 | `S06_Extract` | Extraction: EDC → SAS & R |
| 7 | `S07_SDTM` | Standardization: values snap into SDTM variables |
| 8 | `S08_ADaM` | Analysis: ADaM derives baseline / change / treatment |
| 9 | `S09_Report` | Reporting: Tables, Listings & Figures |
| 10 | `S10_Submit` | Submission to FDA/PMDA → APPROVED |
| 11 | `S11_Close` | The full pipeline: Collect › Extract › SDTM › ADaM › Report › Submit |

Shared pieces: `src/theme.js` (palette/fonts), `src/components.jsx` (backdrop, captions,
titles, cards, the recurring "120 mmHg" data chip). The persistent ink backdrop sits
behind the `<Series>` so scenes crossfade without black flashes.

## Commands
```bash
npm run render -- --composition=ClinStatStory   # or: npx remotion render src/index.jsx ClinStatStory out/clinical_stat_programming.mp4
npm run preview                                  # Remotion Studio (scrub every scene)
npx remotion still src/index.jsx ClinStatStory out/frame.png --frame=430
```

## Narration (voiceover) — implemented via ElevenLabs
Audio is generated by `generate_voiceover.mjs` (ElevenLabs text-to-speech):
1. Put your key in `.env` → `ELEVENLABS_API_KEY=sk_...` (gitignored; never commit).
2. `node generate_voiceover.mjs` → writes `public/scene01.mp3 … scene11.mp3` and
   `src/voiceover.js` (per-scene durations in seconds).
3. `Story.jsx` reads `VO` and sets each `Series.Sequence` length to the narration
   length + a short tail (floored at MIN), and drops an `<Audio>` into each scene.
4. Re-render — Remotion muxes the audio into the MP4.

**Change the voice:** edit `VOICE_ID` at the top of `generate_voiceover.mjs`
(candidate American voices are listed there) and re-run steps 2–4.
**Change wording/pacing:** edit the `SCRIPT` array in the same file and re-run.

## Accuracy notes
Content is deliberately simplified for a first-day audience but technically faithful:
SDTM = tabulation (as-collected, standardized), ADaM = analysis-ready + traceable to
SDTM, TLFs = the reporting layer, Define-XML travels with the datasets in the submission.
The pipeline order (Collect → SDTM → ADaM → TLF → Submit) matches the deck.
